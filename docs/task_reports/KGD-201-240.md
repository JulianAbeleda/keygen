# KGD-201–240 launcher slice

Implemented the reusable launcher state/router slice for the macOS-only
`kg_ddlc_plus` target.

## Packets covered

- KGD-201: typed app registry, central route state, lifecycle, input lock
- KGD-202: first-run/returning-user boot timeline and interaction marker fields
- KGD-210–212: BIOS/BootUp/Login route handoff contracts
- KGD-220: desktop app registry and logical icon IDs
- KGD-221: app-window open/close route ownership
- KGD-222: confirmation, cancel, and save-busy close handling
- KGD-240: launcher/story suspend, ownership handoff, and restoration

## Changed paths

- `crates/kg_ddlc_plus/src/launcher/mod.rs`
- `crates/kg_ddlc_plus/src/lib.rs`

The implementation contains no source paths or proprietary bytes. Launcher
assets are referenced only through validated logical IDs. Public tests use
synthetic state and logical fixtures.

## Acceptance

`cargo fmt --all` and `cargo test -p kg-ddlc-plus`.

Covered assertions include gated BIOS → BootUp → Login → Desktop routing,
store-ready login release, app selection, story handoff and return ownership,
save-busy close protection, cancel safety, and path-like asset ID rejection.

## Limitations and follow-up

This is the deterministic product-state contract. Native macOS window,
CoreAudio, filesystem, and recovered visual layout adapters remain owned by
the later runtime/platform packets. Exact recovered timings and asset catalog
IDs must be wired by the importer/compiler packets; no values were invented
in this slice.
