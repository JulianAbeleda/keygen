# KGD-120, KGD-121, KGD-132 report

Implemented an isolated, fail-closed asset reuse slice for `kg_ddlc_plus`.

## KGD-120 — content-addressed catalog

`crates/kg_ddlc_plus/src/assets/mod.rs` defines the versioned
`keygen.assets.v1` catalog, provenance records, import modes, source/output
hashes, importer version, safe relative blob paths, and a content-addressed
`blobs/sha256/<hash>.png` writer. Duplicate payloads are written once and
catalog validation rejects undeclared blobs, duplicate logical IDs, invalid
hashes, unsafe paths, and incomplete provenance.

## KGD-121 — image importer

`CatalogWriter::import_png` preserves the original PNG bytes and records
decoded RGBA dimensions, pixel hash, color type, and non-transparent alpha
bounds. Indexed PNGs fail explicitly until a palette-preserving translation is
specified. Tests use an original synthetic 1×1 PNG only; no recovered files
are present in the repository.

## KGD-132 — reuse-policy checker

`scripts/check-asset-reuse.py` validates catalog schema, provenance fields,
allowed import modes, uniqueness, declared blobs, safe paths, image metadata,
and (when `--root` is supplied) blob existence and content hashes. It never
requires access to proprietary source files.

Focused command:

```sh
python3 scripts/check-asset-reuse.py --help
```

`cargo test -p kg-ddlc-plus` is currently blocked by a pre-existing compile
error in `crates/kg_ddlc_plus/src/import/ui.rs`: `UiNode` derives `Eq` while
containing `f32` fields. The new assets module itself has no diagnostics; the
error should be removed by the owner of the UI importer task.
