# KGD-431–445 — persistence and reachable-content projection

Implemented the player-owned persistence boundary in
`crates/kg_ddlc_plus/src/state.rs`.

## Delivered

- `SessionState` is a versioned, serde-visible projection for launcher snapshot,
  preferences, unlock events, bounded dialogue history, story variables,
  active save slot, and the fixed 384×216 logical screenshot state.
- Save/load uses `keygen-player::storage::AtomicStore` with the product schema
  `keygen.kg_ddlc_plus.state.v1`; checksum, atomic rename, and sandboxed logical
  paths remain owned by the player crate.
- History is bounded to 512 entries and variables to 256 keys. Progression reset
  clears unlocks, history, variables, and active slot deterministically.
- Validation rejects invalid preferences, viewport dimensions, variable keys,
  and oversized state before bytes are written or exposed to the runtime.
- Synthetic tests cover checksum-preserving round trips, bounded history,
  progression reset, and invalid-state rejection.

## Packet disposition

KGD-430 was already implemented by the reusable `AtomicStore` contract. This
report closes the compatibility projection portions of KGD-431–435 and the
sandbox/reset portions of KGD-440–441. KGD-432–434 remain integration packets:
the story VM, launcher reducer, and individual screen consumers still need to
feed their live snapshots into `SessionState`. KGD-442–445 remain compile-time
and content-coverage gates; this change intentionally does not embed or invent
proprietary script, assets, localization, or achievement data.

The implementation is asset-reuse-first: state stores logical IDs and imported
content values only, never source-package paths or copied artwork.
